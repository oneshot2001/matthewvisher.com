EdgeProof

The problem in the field

Footage gets challenged. I watched it happen for two decades, and the challenge is rarely about what the video shows. It's about whether that file is the file the camera made. The chain of custody for a clip today rests on people and paperwork: who exported it, from which server, and whether anyone believes them. A hash taken at export proves the file hasn't changed since export. It says nothing about the hours before.

Why the usual answers fail

Watermarks are cosmetic. Server-side signing ties trust to the VMS vendor's key, so you're trusting the same system whose export you were questioning. Proprietary evidence formats lock the proof to one player. And most schemes sign the rendered video, which is the wrong object when an analytic fired on a frame and the frame is what matters.

What I built

EdgeProof signs at the camera edge using public PKI. It builds on the MIT-licensed signed video framework, and ONVIF Media Signing v25.12 is the cross-vendor path for H.264 and H.265. Audio is out of scope. The core primitive is the Signed Detection Record: about 500 bytes of CBOR plus a detached COSE_Sign1 signature over ECDSA P-256, signed per detection.

Signed Detection Record   ~500 B · CBOR + COSE_Sign1 (ES256)
  camera_id      device identity, bound to its certificate
  captured_at    camera time of the source frame
  analytic       name + version of what fired
  frame_sha256   hash of the source frame, not a render
  detection      class · confidence · region
  seq / prev     place in the per-camera chain
  sig            detached, ECDSA P-256
  trust_tier     absent by design · the verifier decides

How it works

One record, two envelopes. A standalone CBOR/COSE file that outlives the video, so the proof survives even when the footage is purged, and an ONVIF SEI tag carried inside the stream when the video is retained. Trust is a ladder that the verifier climbs, and the record never claims its own rung. Tier 0 is a software key. Tier 2 is a per-camera key attested by the manufacturer, which is the ship target and depends on vendors implementing it. Tier 3, a factory-burned key, is probably out of reach.

Where it stands

The concept is validated and Tier 0 has shipped: edgeproof-sdr v0.1.0 on July 4, 2026 and v0.2.0 the next day. There is no hosted service. The repository stays private until it has been through a review I'm not going to skip. A software key proves the record wasn't altered after signing; it does not yet prove the record came from that camera. That is the Tier 2 gap, and it is a vendor gap as much as mine.

What's next

A hosted verifier, then pilots with agencies that have a reason to care. The benchmark I've set: a 500-clip test set with zero false confirmations. A verifier that ever says yes to a doctored clip is worse than no verifier at all.
